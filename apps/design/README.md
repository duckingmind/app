# 衣境设计室

衣境设计室是面向电商商品创作的图片工作台。它使用 Proxy App 平台提供的
图片和文本模型，把商品素材整理成商品套图、详情页内容、服饰试穿和风格
复刻结果，并集中保存每次创作的作品和检查报告。

界面统一使用黑白灰主题：黑色主操作、白色画布、浅灰设置区，状态通过文字、
图标与边框区分。主题颜色集中在 `src/styles.css` 的语义变量中维护。

## 功能

- **商品套图**：上传商品原图，选择销售平台、语言、比例和图片类型，生成
  主图及营销场景图。
- **详情页**：选择电商平台、目标市场、文案语言，组合内容模块，统一视觉方向，生成可下载的详情长图。
- **服饰试穿**：选择或上传模特，指定场景和姿势，将服饰应用到模特图上。
- **AI 模特和场景**：根据文字描述生成虚构模特，或为商品推荐拍摄场景。
- **风格复刻**：提供风格参考图和可选商品替换图，控制复刻程度及单图要求。
- **作品管理**：查看历史批次与生成状态；卡片保留图片、标题、下载和「详情」
  入口，检查建议与创作说明在详情中查看，支持 ZIP 下载、继续查询和手动复检。

每个创作模块使用同一块结果画布：没有当前作品时直接展示示例预览；提交
创作后自动切换为当前批次的进度和结果，不需要在「创作预览」与「生成结果」
之间手动切换。顶部导航只负责切换创作类型，设置面板固定在右侧。

加载、任务进度及操作反馈统一显示在悬浮通知区，不占用页面或弹窗内容的
布局空间。任务进度可收起，收起不会停止生成；停止操作保留已有结果。
字段限制和图片自身的状态保留在对应位置，详细错误原因按需展开。

生成前应用会根据所选模型的输入数量、比例和尺寸能力校验请求。每批默认
同时生成最多 3 张图片；某张出图后立即展示，并释放生成名额给后续图片。
图片检查使用独立队列，同时检查最多 2 张，不占用生图名额。检查中、未检查
或有检查建议的图片均可直接预览和下载；卡片仅显示简短检查状态，完整建议
在「详情」查看。检查结果用于辅助核对商品或人物一致性、构图和明显缺陷。

图片模型和文本模型目录独立加载；一侧接口暂时失败时，另一侧仍可继续使用，
应用会保留已加载的模型并提示刷新。模型目录恢复后才会清除降级状态。

同一页面可以切换模块并同时启动多个独立批次；批次各自保存状态和停止信号，
页面会合并展示进行中的阶段。每批默认最多并发生成 3 张图片，账户层仍受平台
媒体任务并发额度限制，超过额度的提交会保留为失败或待继续任务，不会自动重复扣费。

## 素材要求

- 每批最多上传 6 张商品或服饰原图；单张支持 JPG、PNG、WebP，大小不超过
  10 MB。
- 图片边长至少 64 像素，总像素不超过 4,000 万。
- 模特参考最多 25 张，风格复刻最多 20 张参考图，并可另外提供最多 6 张
  替换商品图。
- 生成规格取决于所选模型的能力；应用会禁用不支持的比例或输入数量。
  模型选项会说明不可用原因；试穿及替换商品的复刻需要至少支持两张参考图，
  AI 模特需要文字生图能力。

移除、替换素材或新建任务时会释放不再使用的临时图片。图片下载和处理校验
JPG、PNG、WebP 格式及文件内容，单张下载上限为 80 MiB；处理时最多支持
4,000 万像素及 30,000 像素单边，并设置超时，避免一直停留在加载中。
详情长图逐张解码拼接，源文件总大小上限为 80 MiB，成图上限为 3,600 万像素。
ZIP 导出会清理文件名中的路径字符，分块写入并限制总内容为 128 MiB；超过
限制时可减少选中作品后分批下载。

请求返回任务编号时，应用会继续查询任务，不会因为页面刷新而重复提交。
主动停止或遇到首个生图失败时，应用不再提交后续图片，也不会自动重试。
已提交的任务仍可能完成，返回的图片和任务编号会保留；已有结果始终可下载，
待处理任务可在作品中继续查询。图片检查失败只影响该张报告，不阻断其他图片
生成。刷新后未完成的检查会显示为未完成，不会一直停留在「检查中」。参考素材与复检预览仅保留在当前页面，刷新后需重新选择素材。生成结果通过任务编号或资产编号恢复，展示和下载时重新获取有效地址；旧版本未保存编号的作品仍保留原链接供及时下载，但链接到期后无法保证恢复。

## 运行

首次在 `app` 目录运行 `npm ci` 并构建共享 SDK，再在 Design 子应用目录执行：

```bash
cd app
npm --prefix proxy-app-sdk run build
cd apps/design
npm run dev
```

首次连接或请求模型时，开发环境可能要求完成平台登录。只运行 `npm run dev:server`
可以预览界面，但没有平台开发运行时，图片生成、文本规划和用户
存储不会工作。

## 测试、构建和打包

```bash
npm run test
npm run pack
```

打包会自动构建并校验应用。只构建前端资源可用 `npm run build`；完整构建可用 `npx proxy-app build`，随后可运行 `npm run validate` 单独校验。

浏览器回归可在 `app/apps/design` 目录执行 `npm run test:ui`。测试使用本地
Chrome/Chromium 与隔离的平台模拟数据，不调用真实模型；测试会自动查找常见安装位置，
也可用 `DESIGN_BROWSER_PATH` 指定浏览器可执行文件。

登录回归执行 `npm run test:auth`，使用真实 SDK 和隔离的本地 OAuth 服务，
覆盖登录弹窗、回调与轮询恢复、账户标识缺失、弹窗被拦截和宿主登录。
仅在登录状态与账户标识都确认有效后加载模型、作品和偏好；连接故障可重试，
不会自动反复打开登录窗口。

打包文件默认写入 `app/apps/design/dist/design.zip`。上传 ZIP 到开发者控制台后，在宿主
中测试版本，检查图片模型、文本模型、权限和下载流程，再提交发布。

应用清单需要 `storage.user`、`model.images` 和 `model.responses`。应用通过
`@ducking-mind/proxy-app-sdk` 访问平台能力；用户数据按账户隔离保存，模型
服务凭据不会放入应用包。

作品和偏好使用平台通用 KV 保存到服务端。历史最多保留 40 项，索引指向不可变的作品详情。
详情变更和索引版本校验在同一事务提交；超过 1 MiB 时先分块暂存独立详情，最后条件提交索引，
旧详情仅在索引提交成功的同一事务中删除。多个窗口同时修改时明确报告冲突，要求重新加载核对，
不会覆盖另一窗口的内容。保存响应丢失时复用原操作与幂等键，提交前必要保存失败会中止生成。

图片文件由平台媒体资产服务保存。KV 仅保存 taskId、assetId 和作品元数据，不写入图片 Base64 或
新生成结果的签名 URL；模型返回任务编号后会先保存编号再轮询。参考图及复检预览仅留在页面内存中，
不使用 KV 模拟文件上传。旧版本无稳定素材编号的记录不会因自动保存而丢失原链接，应及时下载。
