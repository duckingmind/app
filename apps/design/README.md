# 衣境设计室

使用当前仓库的 React、TypeScript、Vite 和 `@ducking-mind/proxy-app-sdk` 实现商品创作工作台，参考 DesignKit 的[商品套图](https://www.designkit.cn/product-kit)、[详情页](https://www.designkit.cn/product-kit/detailpage)、[服装试穿](https://www.designkit.cn/product-kit/try-on)和[爆款复刻](https://www.designkit.cn/product-kit/clone)流程。应用通过 Proxy 平台图片编辑、图片生成和 Responses API 工作，没有复制或接入 DesignKit 的私有生成服务。当前版本为 `0.2.0`。

## 功能与机制

| 环节 | 实现 |
| --- | --- |
| 商品套图 | 最多 6 张商品原图，支持电商平台、市场、语言与比例设置。智能模式由模型根据商品动态分配 7 张图片的用途，至少包含 1 张白底主图；自定义模式按所选类型和数量生成 7–20 张。支持 AI 帮写、视觉风格建议和可选的上架标题/卖点/描述。 |
| A+ / 详情页 | 最多 6 张商品原图，16 种内容模块（默认 6 种），按用户选择顺序生成。支持统一风格、AI 帮写、市场与语言选择；全部模块完成后按顺序拼接下载详情长图。 |
| 爆款图复刻 | 最多 20 张参考图片、6 张可选替换商品图。支持 6 种设计类型、参考风格/高度复刻两种程度、统一要求和每张图的独立要求；每个任务只使用对应的参考图。 |
| 服饰素材 | 上传最多 6 张 JPG、PNG 或 WebP，每张不超过 10 MB；支持拖放、预览和移除。图片边长至少 64 像素，面积不超过 4000 万像素。 |
| 模特 | 25 张参考模特、上传自有模特、根据文字生成 AI 模特。生成的模特可继续用于试穿。 |
| 场景与姿势 | 7 个预设场景、自定义场景、AI 场景推荐，以及 4 个拍摄姿势。多选场景与姿势形成组合，逐张生成。 |
| 图片规格 | 从平台模型目录读取编辑能力、输入图片上限、支持比例、固定尺寸或动态尺寸约束；只提交经过校验的尺寸。 |
| 逐图规划 | 商品套图、详情页、复刻均先通过 Responses 生成严格 JSON 计划，校验完整性后才提交图片生成。记录整组视觉方向与每张独立方案。 |
| 成图检查 | 商品套图、详情页、复刻、试穿和 AI 模特均逐张核对成图，展示通过、需人工核对或检查不可用的独立状态，支持手动继续检查。 |
| 作品 | 当前批次、历史记录、创作方案、检查报告、状态筛选、任务继续查询、单图下载、ZIP 打包下载，以及与当前模特的滑动对比。 |

试穿首先将模特放在第一张参考图，再附上服饰图，以多图编辑请求提交到 `/images/edits`。提示词分别约束人物身份、服装细节、场景和姿势。输入数量超过模型的 `max_input_images` 时，将服饰合成带编号参考板，提交“模特 + 服饰参考板”两张图。因此试穿要求模型支持至少两张参考图；参考板方式也会压缩单件服装的有效细节。

AI 模特使用 `/images/generations`。AI 场景推荐将服饰参考板作为图片输入调用 `/responses`。文案、推荐、规划与成图检查共用顶部“生成设置”中的文本与图片理解模型。

文本模型目录会排除明确不支持图片输入、文本输出或 Responses 的模型；缺少能力元数据的模型保留为“待验证”，不会仅凭名称判断兼容性。首次使用所选模型前，应用生成一张包含随机数字码的图片，通过真实 `/responses` 请求核对模型是否能读出图片中的答案，答案不会写入请求文字。通过结果仅缓存到当前账户连接；重新连接账户后重新验证。验证失败会显示错误，不会将模型标记为可用。

三个商品模块均调用 `/images/edits`：套图和详情页输入同一商品的多个角度；复刻将风格参考放在第一张，替换商品放在后续图片。超出模型输入上限时，仅将同一组商品图合成 PRODUCT 参考板；风格参考与商品身份保持分开。替换商品至少要求模型支持 2 张输入，没有替换商品的复刻可使用单图编辑模型。

三个商品模块均先读取商品与对应风格参考，调用 `/responses` 制定逐图计划，再调用图片编辑接口。模型返回一个包含 `direction` 和 `jobs` 的 JSON 对象；每个位置使用固定 ID，并包含类型、标题和独立图片指令。智能套图允许模型在受限类型中自由组合 7 张用途，至少包含 1 张 `main` 主图；自定义套图、详情页和复刻必须保留所选类型、数量、顺序、标题及参考图绑定，只细化各张内容。解析器严格拒绝缺项、未知字段或类型、重复 ID、数量与顺序变化、超长内容、重复逐图指令及非法 JSON；无效计划不会静默回退为固定提示词并开始生图。

每张图片使用整组视觉方向与自己的独立方案，原始商品信息、模块要求和主图白底等硬性约束保持优先。方案会随作品保存并可查看。规划使用普通 Responses 请求，不依赖供应商是否实现 `json_schema`；返回内容完整解析，不截断 JSON。上架文案是独立的可选调用。风格建议基于产品外观和平台常见视觉习惯，不涉及实时销量或竞品抓取。

每张成图返回后，应用将对应原始素材的压缩预览、创作要求、方案与成图一起交给图片理解模型，核对商品/人物一致性、可辨认文字、明显变形和当前图片用途。AI 模特没有原始身份参考时，仅核对形象描述、构图和人体结构，不宣称完成身份一致性比对。检查结果采用严格 JSON，报告状态为 `passed`、`needs_review` 或 `unavailable`。检查失败、停止或模型无法读取时保留已生成图片，可稍后手动继续检查；检查不会自动重生图片，也不会重复提交图片生成请求。检查结论不等同于平台合规保证，无法辨认的细节会要求人工核对。

详情长图仅合成真实生成结果。应用记录原始批次总数和模块顺序，缺失、未完成或已移除模块的批次不能被导出为完整长图；长图宽度最大 1200 像素，高度最大 30000 像素，超限可改用分图 ZIP。上架文案可单独复制，并包含在 ZIP 中。所有模块的作品可在“我的作品”统一查询和恢复。

## 任务与保存

图片请求同时兼容同步图片结果与异步任务。如果平台返回任务编号，或 SDK 的错误详情中携带已受理的任务编号，应用查询 `/images/tasks/{id}`，不会重新提交生成请求。每个生成任务使用稳定的幂等键；批次遇到失败或无法确认的结果会停止继续提交。

“停止后续生成”停止尚未提交的任务和后续轮询。已经提交的 POST 会先等待响应或任务编号，避免丢失已受理任务；平台任务仍可能完成并计费。当前平台接口没有任务取消能力。有任务编号的未完成作品可以继续查询，明确失败的任务保留失败状态。

作品通过 SDK Bridge 写入当前账户的 `storage.user`，使用“紧凑历史索引 + 逐任务详情”的结构。`design:works:v1` 索引最多保留最近 40 条记录，包含作品 ID、批次、任务状态、顺序以及详情与复检素材键；每张作品的完整要求、创作方案、文案、检查报告和图片地址分别存入 `design:work:{作品 ID}`。每份详情和索引分别受 180,000 字节上限约束，单份超限会明确报错，不会按整批长提示词的累计长度静默截掉后续任务。保存时先验证所有详情，写完详情后再提交索引；读取兼容旧版完整作品数组，后续保存转为新结构。

成图仍只持久化 HTTP(S) 图片 URL 与任务信息，不保存成图二进制。仅返回 Base64 且没有任务编号的完成作品无法跨刷新恢复，应在当前页面下载；远程图片 URL 的有效期由平台或供应商决定。刷新时，未完成且有任务编号的记录，以及只有 Base64 结果但保留了任务编号的完成记录，恢复为待查询，可通过“继续查询”重新获取平台结果；无任务编号的队列记录恢复为已跳过。

为了刷新后继续检查，应用另行保存每张作品的复检上下文：商品/服饰原图合成 PRODUCT 预览，模特或风格参考合成独立 STYLE 预览，保持两者含义分开。每张预览最长边不超过 960 像素，根据容量继续降低分辨率或 JPEG 质量，内联字符串不超过 80,000 字符；每份上下文最多 2 张预览，总计不超过 180,000 字节。它们以 `design:review:{作品 UUID}` 单独写入 `storage.user`，历史只保存 `reviewKey`。原始完整上传文件不会持久化。复检读取这些压缩预览，细小文字或纹理可能仍需人工对照原文件核对；无复检上下文的旧作品不能宣称已完成原图一致性检查。

作品从持久化历史中删除或因 40 条数量上限被淘汰后，会清理对应任务详情和 `reviewKey` 的独立存储内容。清理失败不会改变已提交作品的状态，下一次保存会重试清理。商品任务会在提交图片生成前先保存创作方案和复检上下文。模型能力验证、逐图规划、可选文案、图片生成及成图检查均使用当前账户的真实模型额度；手动继续检查也会产生新的模型请求，但不会触发图片重生。

## 本地运行

建议使用 Node.js 22.12 或更新版本；测试命令依赖 Node 的 TypeScript 类型剥离支持。在仓库的 `app` 目录执行：

```bash
npm install
npm run sdk:build
npm run design:dev -- --port 5176
```

开发地址为 `http://127.0.0.1:5176/`。端口被占用时换用其他端口。`design:dev` 通过 `proxy-app dev apps/design` 启动平台 Relay，应用首次连接账户时打开平台登录窗口，模型调用使用登录账户的真实权限、额度和计费。

本地开发需要运行 Portal、管理 API 和模型网关，默认 Portal 为 `http://localhost:9004`、管理 API 为 `http://localhost:9003/api`。如部署地址不同，在启动 CLI 前配置 `PROXY_PORTAL_URL` 和 `PROXY_API_BASE_URL`。Relay 的网关、Bridge 和认证地址由 CLI 注入，不需要手工配置到应用。

应用已在本地开发者账户注册为草稿，标识为 `app.proxy.202609081545090f11`。已配置本地 `.proxy-app.json`，绑定平台应用 `app_2026090815450926dd`，该文件由 Git 忽略且不进入发布包。首次连接需要在平台登录页面完成登录；弹窗不可见时可点击应用提供的“打开登录页面”。其他环境需要先创建或关联自己的平台应用；CLI 的 `create` / `link` 管理命令使用当前平台管理会话，应用运行时使用独立的 App Session。

仅检查页面布局与素材时，可运行独立 Vite 预览：

```bash
npm --workspace proxy-design-app run dev -- --host 127.0.0.1 --port 5177
```

该方式不创建平台 Relay，无法独立完成模型调用与账户存储。

## 验证与打包

在 `app` 目录执行：

```bash
npm run design:test
npm run design:build
npm run design:validate
node cli/proxy-app.mjs doctor apps/design
npm run design:pack
```

产物为 `app/dist/design.zip`。正式运行时由平台 AppHost 在 iframe 中创建 App Session，应用权限为 `storage.user`，模型能力为 `model.images` 和 `model.responses`。发布包需要上传到开发者中心，并通过版本自测后再发布。

当前 77 项自动化测试及构建已通过，覆盖模型能力与图片挑战验证、严格逐图规划、成图检查解析、复检上下文存储、请求构造、任务恢复及交互状态。真实联调中，`gpt-5.5` 已通过图片数字挑战验证，并成功返回上架文案与逐图规划；本次图片供应商在提交阶段返回 HTTP 403 / Cloudflare 拦截，应用正确停止后续图片提交并保留失败与未提交状态。另已用 `gpt-5.5` 对公开示例完成一次质量检查，返回 `needs_review`；这不代表本应用真实生成效果已验收。参考作品是下载的原站图片，不代表本应用的生成结果；最终质量取决于平台模型、参考素材和提示词。

## 代码与素材

- `src/main.tsx`：工作台界面、账户连接、批次和作品管理。
- `src/core.ts`：模型能力、尺寸校验、提示词、生成与轮询、历史序列化。
- `src/images.ts`：上传校验、图片归一化、参考板和下载。
- `src/productModule.tsx` / `productCore.ts`：商品套图界面、内容规划与提示词。
- `src/contentModules.tsx` / `contentCore.ts`：详情页、复刻界面与逐图请求。
- `src/planning.ts`：结构化逐图策划提示、严格 JSON 校验、固定位置与引用约束，以及独立成图指令合并。
- `src/textModels.ts`：文本模型能力筛选与真实图片数字挑战验证。
- `src/quality.ts`：成图核对提示、检查报告类型与严格 JSON 解析。
- `src/reviewContext.ts`：原始素材压缩预览、复检存储键与上下文格式校验。
- `src/workStorage.ts`：紧凑历史索引、逐任务详情持久化、旧历史兼容与淘汰详情/复检素材清理。
- `src/commerce.ts`：商品创作的串行队列与参考图输入规则。
- `src/WorksPanel.tsx`：共用作品、创作方案、检查报告、手动复检、文案与详情长图导出入口。
- `src/assets/`：78 张优化后的 WebP 参考素材，以内联资源使用，避免生产 iframe 不透明来源导致素材读取失败。
- `tests/`：核心行为、模型能力验证、逐图规划、成图检查、复检上下文、详情/复刻输入以及批次停止恢复的回归测试。
- `references/`：原站公开素材与来源清单，详见 [素材说明](references/README.md)。
- `references/modules/`：三个新增模块的 34 张公开素材、来源清单和功能研究记录，详见 [模块参考说明](references/modules/README.md)。
