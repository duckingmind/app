# 应用发布规范

本文介绍公开应用包格式、应用开放申请和版本发布流程。平台负责托管构建文件、处理用户登录并提供已审核的运行能力。应用应是前端发布包，不应包含平台凭证或私有服务地址。

## 发布流程

```text
proxy-app init
  -> 新应用使用 proxy-app create；已有应用直接使用其公开 slug 写入 manifest.id
  -> 使用 proxy-app dev 开发
  -> 构建并校验
  -> 打包并上传版本
  -> 配置应用收费，在应用卡片申请开放
  -> 应用开放审核通过，所附版本成为线上版本
  -> 后续版本上传并测试
  -> 手动设为线上版本，或切换历史已发布版本回滚
```

审核对象是整个应用的开放申请，系统自动关联最新已上传版本供平台预览。每次申请都有独立编号，版本只是审核材料。创建应用和本地调试不需要审核。每个应用同时只能有一个待审申请，可以撤回后更换预览版本；驳回原因会在“我的应用”显示。

每个上传版本都是不可变的。修改应用包时必须提高 `manifest.version` 后重新构建、上传；未修改应用包时，可直接重新申请开放。应用开放后，上传只保存候选版本，不切换线上。测试完成后通过“设为线上版本”或 `proxy-app publish` 手动发布，无需重复审核。历史已发布版本可通过“切换到此版本”或 `proxy-app publish --version <version>` 回滚，也可再次切回新版；不限制目标版本号必须更高。

暂停或禁用的应用发布新版后仍保持原状态。开发者暂停时，已有有效会话可继续使用，应用不再对外展示或接受新用户打开；平台禁用时停止运行，开发者可以上传修复包，但不能自行解除限制。详细状态、操作与异常处理见 [应用开放与版本管理](APP_LIFECYCLE.md)。

本地调试创建的草稿尚未包含上传文件，可以直接上传同版本 ZIP，保留原版本记录。
重复上传完全相同的 ZIP 会返回已有版本，不会重复发布；同版本的不同 ZIP 会返回
`APP_VERSION_CONFLICT`，需要修改 `manifest.json` 中的 `version` 后重新构建、打包，
仅修改 ZIP 文件名无效。`proxy-app publish` 会先为本地草稿上传构建文件，再根据应用是否已开放，选择提交应用开放申请或直接发布版本。

应用分类统一为电商（`ecommerce`）、漫剧（`comic`）和其他（`other`，默认）。创建时可通过 `proxy-app create apps/my-app --category ecommerce` 指定，之后可在“编辑应用资料”中调整。分类属于应用资料，无需随每次版本上传重复配置。

## 删除未使用的草稿

在“我的应用”中，可以删除从未提交审核、从未发布的草稿应用，包括已有本地调试版本或
已上传但尚未提交的版本。确认框会显示应用标识和版本数量，删除后无法恢复。

删除会移除应用及草稿版本记录，清理应用内测试数据，并使相关调试会话失效；已产生的
用量、账单和审计记录会保留。已提交审核、已驳回或已发布的应用暂不支持删除；已上架的
应用可通过“暂停上架”停止展示。删除草稿应用后，系统会在删除数据库记录后立即尝试清理版本包和图标对象；对象存储故障时会记录清理失败，需按运维告警重试。

## Manifest

manifest 位于应用源码根目录，并会被放在发布压缩包根目录：

```json
{
  "schema": "proxy.app/v1",
  "id": "app.example",
  "version": "1.0.0",
  "name": "示例应用",
  "description": "面向应用市场的简短介绍。"
}
```

必填字段为 `schema`、`id`、`version`、`name`。应用入口统一为包根目录的 `index.html`，不再在 manifest 中声明 `runtime`。正式应用标识由平台创建应用时分配。已有应用上传时，ZIP 中的 `manifest.id` 必须与上传目标应用的公开 slug（或平台返回的稳定 app_id）一致；直接使用公开 slug 即可，无需 `proxy-app link` 或 `repair`。新应用才使用 `proxy-app create` 取得标识。

可选声明：

| 字段 | 可选值 | 用途 |
| --- | --- | --- |
| `permissions` | `user.profile.read`、`platform.capabilities.read`、`storage.user`、`notification`、`theme.read`、`locale.read` | 宿主权限，可省略；默认提供全部公开权限，显式列表可缩小宿主范围。 |
| `apis` | `model.responses`、`model.chat`、`model.messages`、`model.embeddings`、`model.images`、`model.videos`、`model.music`、`model.voice_design`、`model.tts` | 兼容性的能力元数据，可省略；不参与 Gateway 授权。实际调用由平台签发的 App Session 或 API Key scope、账户权益和路由策略决定。 |
| `pricing.mode` | `commission` | 可选的兼容元数据；正式收费在“我的应用”中设置，首次申请开放和新版本发布必须使用抽成。 |

桌面端构建和宿主兼容性由平台私有发行流程管理，不通过应用 manifest 单独开关或配置入口。
Web 应用和私有 Electron 宿主都使用包根目录的 `index.html`。

应用默认通过平台 Gateway 运行，因此 `backend` 可以省略（默认 `platform`）。`pricing` 可省略，显式声明时仅支持 `commission`，用于提供初始抽成提示；正式收费由应用市场保存，省略时需在申请开放前填写抽成比例。

新应用不需要填写这四项。`permissions` 省略时，平台自动为会话分配公开宿主权限；`apis` 仅作为
兼容性的能力目录，不是数据面授权边界。主机权限在创建会话时从已审核版本解析，不建立或修改永久用户授权记录。

应用统一通过同源入口和 HttpOnly App Session Cookie 运行，浏览器脚本不会拿到 `ast_` Token。平台根据已保存应用记录和
发布状态决定是否允许运行。Gateway 路由仍按平台签发的会话
scope、账户权益和路由策略校验；`apis` 列表不会额外收窄数据面能力。

应用不需要安装，用户可直接打开已开放的应用。开发者在应用卡片的“设置收费”或“修改收费”中设置按调用抽成比例，收费不再区分免费和抽成。首次申请开放时，CLI 可使用 manifest 中的设置初始化收费；已保存配置时则复用应用配置。新开放申请和新版本发布必须设置有效抽成比例，已保存比例只能降低。审核中需先撤回才能调整。已开放应用保存收费后，在下次发布新版本时生效；候选版本首次发布时继承最新保存配置，不从 manifest 重设收费。历史已发布版本可保留一次性收费快照用于审计，但用户现可免费打开，既有订单不重写。仅支持回切历史抽成版本，未设置抽成的历史版本不能重新设为线上版本。切换历史抽成版本会恢复其原比例；界面切换前展示当前与目标收费。保存的待生效配置不随回滚改变。

旧版本或历史订单中的 `one_time` 数据只作为审计记录兼容，不可新建或重新启用。历史免费和一次性收费应用可明确设置抽成后重新提交或发布新版本；旧版本与订单保留原始价格快照，不会被改写。

“我的应用”只保存最近使用和置顶偏好。首次打开直接创建用户与应用绑定的会话，不写安装记录；置顶无需先打开，取消置顶不撤销当前会话。旧 `/install` 和 `/launch` 接口保留兼容，但都只返回打开元数据。

公开接口仍需有效 App Session；账户身份、配额、计费和平台审核照常校验。

## 发布命令

公开 CLI 只打包 Web 应用；桌面宿主和桌面发行包由内部私有流程维护。

```bash
proxy-app build apps/my-app
proxy-app validate apps/my-app
proxy-app pack apps/my-app /tmp/my-app.zip
proxy-app upload apps/my-app
proxy-app publish apps/my-app
proxy-app publish apps/my-app --version 0.1.4
```

`build` 生成发布文件，`validate` 校验 manifest 和构建结果，`pack` 自动重新构建、校验并生成压缩包，`upload` 自动构建打包并上传不可变版本，不切换线上。`publish` 在应用尚未开放时提交应用开放申请；开放后，显式将目标版本设为线上版本，命令不会重复提交审核。`publish --version <version>` 仅选择已有远端产物，不构建、不上传，也不要求修改本地 manifest。已有待审申请时，请先等待结果或在“我的应用”的应用卡片撤回。

管理命令请使用平台官方登录方式或 CI 的密钥配置。发布凭证必须放在源码目录之外，不能暴露给应用 JavaScript。

## 审核清单

申请开放前请确认：

- 应用可以从声明的入口文件启动，并能在全新安装中正常工作。
- 应用名称、描述、截图和权限申请与实际行为一致。
- 外部图片、字体、代码和模型提示词具有可再分发许可。
- 用户数据遵循最小化原则，并支持按用户请求删除。
- 网络失败、能力不可用、空结果和长时间任务都有明确界面状态。
- 发布压缩包只包含构建后的应用和公开元数据，不包含凭证、开发环境文件、调试转储或无关源码。

首次审核通过后，平台会向用户提供候选版本。后续上传不切换线上；手动发布或回滚会切换当前发布版本；普通用户下次打开或创建运行会话时使用当前版本，已经运行的会话不会被强制刷新。缺省权限随新会话自动补全；仍使用显式权限列表的应用，新增列表项需用户授权。开发者可以在“管理版本”中测试指定版本。
