# 应用包与运行授权加固

这份说明定义公开应用包从构建到受控宿主安装的信任边界。桌面宿主和发布流程属于私有组件；它补充了[安全策略](../SECURITY.md)，包签名不能用应用内的管理令牌代替。公开仓库的边界见[桌面端代码边界](DESKTOP_BOUNDARY.md)。

## 构建与扫描

`proxy-app pack` 会在生成 ZIP 前检查构建目录中的符号链接、源码映射、私钥文件和高置信硬编码凭证。正式上传必须使用构建产物，源码包只用于本地调试；CI 应运行：

```bash
npm audit --audit-level=high
npm run verify:all
```

扫描只检查可识别的泄漏模式，不能替代代码审查、依赖锁定或凭证轮换。发现凭证后应立即撤销并重新发布，不能仅删除文件后继续使用原凭证。

## Ed25519 包签名

发布服务为每个应用包生成签名信封。受控宿主按平台 origin 选择可信公钥，并在安装和启动前校验签名、包摘要与安装目录文件。生产配置应满足：

1. `require_signatures` 为 `true`。
2. 每个允许的生产平台 origin 都有明确的 Ed25519 公钥；不要使用开发环境的密钥。
3. 密钥名称保持稳定，轮换时同时保留旧公钥直到所有仍受支持的版本完成更新。
4. 私钥只存在于发布机或 CI 密钥管理器；不写入应用 ZIP、更新元数据或仓库。

公开仓库不包含宿主信任根或生产公钥。私有发布流水线必须使用部署系统生成的受保护配置，并在发布检查中拒绝空公钥或 `require_signatures: false`。

## 会话与安装权限

应用运行时只接收短期 App Session；桌面宿主不会把平台管理令牌或模型供应商密钥注入应用。安装包下载、版本状态和用户权益由服务端校验，客户端不能通过修改 manifest、版本号或本地文件来获得其他应用或账户的权限。

发生签名校验失败、摘要不一致、过期会话或版本撤销时，应停止安装或请求用户重新从平台获取包。不要回退到任意 URL、跳过签名检查，或复用已失败的安装目录。

## 发布前清单

- 使用锁文件安装公开工作区依赖，并在私有桌面流水线中单独审计桌面依赖。
- 使用全新的构建目录运行 `npm run verify:all`，确认 CLI、SDK 和子应用测试通过；桌面测试由私有流水线单独执行。
- 在私有发布流水线检查生产信任根的 origin、公钥和签名要求；开发兼容配置不得进入生产包。
- 保存构件 SHA-256、签名密钥版本和发布版本之间的对应关系，便于撤销和回滚。
