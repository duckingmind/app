# 应用开放与版本管理

**审核对象是应用的对外开放申请。版本是申请附带的预览材料，不单独进行版本审核。创建应用、开发调试和开放后的版本发布无需重复审核。**

## 从创建到申请开放

1. 在“我的应用”创建应用，或执行 `proxy-app create`，取得应用标识。已有应用只需把公开 slug 写入本地 `manifest.id`，无需执行 `proxy-app link` 或 `repair`。
2. 本地开发、构建并上传候选版本。仅在本地调试的版本没有发布文件，不能作为开放申请的预览材料。
3. 测试完成后，在应用卡片点击“申请开放”，只需设置按调用抽成比例。系统自动关联最新已上传版本作为预览材料；配置保存后，审核候选版本与后续新发布版本继承。撤回或驳回后重新申请时，默认保留已保存的抽成比例，允许降低比例。
4. 平台管理员在“应用审核与管理”打开该应用的开放申请，预览所附版本，检查应用信息、权限、收费与完整应用包，批准或填写原因后驳回。
5. 批准后，应用对外开放并进入市场，候选版本成为当前发布版本。驳回原因显示在应用卡片上，开发者完成修改后重新申请。

同一应用同时只能有一个待审开放申请。每次申请都有独立编号，并固定关联一个预览版本。审核期间可以继续上传版本；更换预览材料前，在应用卡片撤回当前申请，再重新申请。撤回和驳回都会保留记录；旧申请页面不能批准或撤回新的申请。应用包不可覆盖：修改代码后请提高版本号并重新构建上传；未修改应用包时，可以直接重新申请开放，系统继续关联最新已上传版本。

应用收费统一按美元（USD）计价，无需选择结算币种。在应用卡片的收费区域点击“设置收费”或“修改收费”，可以独立保存配置，无需重复申请开放。已开放应用会同时展示当前生效收费和下次发布的收费；修改在下次发布新版本时生效，当前已发布版本、已有会话和历史订单保留原收费快照。尚未开放的应用在申请开放时采用已保存配置。

用户无需安装应用，可直接打开已开放应用。新应用和新版本统一按调用抽成，比例保存后只能降低。历史一次性收费不再对新用户收取；历史免费或一次性收费应用需明确设置抽成后再提交或发布新版本，历史版本和订单继续保留原价格用于审计。审核中的申请需先撤回再调整收费；取消或保存失败不会修改原收费设置。应用暂停或被平台禁用时也可修改配置，但不会自动恢复开放。

“管理版本”用于上传、测试和手动切换线上版本；申请、撤回、审核结果属于应用。上传只保存候选版本，不切换线上版本，不替换正在审核的材料，也不会自动增加开放申请。

名称、说明和分类可以在“编辑资料”中修改。存在待审申请时，先撤回再修改，保证审核期间的资料不变。保存基础资料不会改变应用标识、收费方式或上架状态；被平台禁用的应用也可修复资料，但仍需管理员解除限制。

## 应用开放后的手动发布与回滚

- 上传新版本后保留为候选草稿，当前线上版本继续提供服务。测试完成后，在“管理版本”点击“设为线上版本”并确认；CLI 的 `proxy-app publish` 是同样的显式发布动作，应用开放后无需重复审核。
- 历史抽成版本可点击“切换到此版本”，用于回滚或再次切回新版。切换不要求目标版本号更高，不重新构建或覆盖历史包；当前线上版本不重复切换。
- CLI 使用 `proxy-app publish --version 0.1.4` 选择已上传版本，无需修改本地 manifest。普通 `publish` 使用本地 manifest 版本，缺少上传产物时先构建上传。
- 完全相同的 ZIP 重复上传只返回已有版本，不改变线上版本；同一版本号上传不同内容会失败。
- 手动切换成功后，创建者与普通用户通过正式地址下次打开时使用所选版本，正在运行的会话不被强制刷新。新会话采用该版本经审核的宿主权限，无需建立安装记录或另行确认权限。
- 版本管理中的“测试版本”使用带 `?version=...` 的独立预览地址，仅创建者可用；预览旧版或草稿不会固定正式打开地址。
- 候选版本第一次发布时继承最新保存的应用收费配置。切换历史已发布版本时保留该版本原有收费快照，确认框显示当前与目标收费；新会话按所选版本执行，已有会话和订单不重新计费。回滚不改变已保存的待生效收费，后续新版本仍采用该配置。
- 未设置抽成的历史版本不能重新设为线上版本；仍在线的历史版本可继续使用，设置抽成并发布新版本后完成迁移。
- 新收费配置的抽成比例只能降低；回滚历史版本可能恢复该版本原有的较高抽成，不修改历史快照或抬高新配置的上限。
- 发布和回滚均保留应用的暂停或平台禁用状态。

## 应用状态与下一步

| 应用状态 | 是否对外可用 | 开发者下一步 |
| --- | --- | --- |
| 待开放 | 仅开发者调试 | 上传并测试版本，在应用卡片申请开放。驳回后查看原因、修复并重新申请。 |
| 开放审核中 | 仅开发者调试 | 等待应用开放审核；需要更换预览材料时先撤回申请。 |
| 已开放 | 市场展示，可直接打开和运行 | 上传并测试候选版本，手动发布或切换历史版本，或暂停开放。 |
| 已暂停上架 | 不展示、不接受新用户打开；已有有效会话可继续使用 | 可发布新版；准备好后恢复开放，无需重新审核。 |
| 平台已禁用 | 不接受打开和运行，已有运行会话失效 | 查看平台原因、上传修复版本，等待管理员解除限制。 |

应用、开放申请和版本分别展示状态：例如“版本已上传、应用开放审核中”，表示该版本可用于预览；“版本已发布、应用已暂停”，表示新版已经就绪，但应用仍未重新上架。开放申请被驳回不代表所附版本被判定为不可用，它仍可测试并作为下一次申请的材料。

管理员解除已开放应用的限制后，应用进入“已暂停上架”，由开发者决定何时恢复。尚未开放的应用恢复为原有待审或草稿状态，仍需完成开放审核。解除限制不会恢复已经失效的运行会话，用户重新打开应用后创建新会话。

## 审核与管理记录

后台支持按待审、已上架、已暂停、已禁用、草稿或全部应用筛选。审核完成后，应用仍可在对应列表中管理，并查看版本和操作记录。

打开应用的开放申请后，点击“打开预览”即可查看该申请所附版本的完整页面及其脚本、样式、图片，支持页面交互、刷新和返回审核详情。版本历史也支持查看、预览和下载，审批只在应用申请中进行。预览链接有效期为 15 分钟，过期后可重新打开；仅本地调试、尚未上传应用包的草稿不能预览。

审核预览在隔离环境中运行，不会自动安装应用或授予账户权限。预览用于检查界面和本地交互；模型调用、账户数据等功能需通过应用用户会话验证。打开、刷新或关闭预览不会改变审核结果。

资料修改、收费修改、提交、撤回、通过、驳回、版本发布及切换、暂停、恢复、平台禁用及解除限制都会记录操作时间和结果。版本切换记录包含原版本与目标版本。状态操作与对应记录一起保存，失败时不会留下“状态已改变但记录缺失”的半完成结果。

后台下载的审核包包含已托管的入口文件、脚本、样式和其他资源。它由托管文件重新打包；页面中的“原上传包 SHA256”对应开发者上传的原 ZIP，重新打包后的 ZIP 校验值可能不同。

## 常见情况

| 情况 | 处理方式 |
| --- | --- |
| 找不到修改收费入口 | 在“我的应用”卡片收费区域点击“修改收费”。保存后发布新版本，调整才对用户生效。 |
| 找不到申请开放入口 | 到“我的应用”的应用卡片操作；先上传一个可用于预览的完整应用包。 |
| 已有待审申请，需要更换预览版本 | 等待结果，或在应用卡片撤回原申请后重新申请。 |
| 上传后线上仍是旧版 | 上传不切换线上。在“管理版本”测试候选版本后，点击“设为线上版本”并确认。 |
| 新版出现问题，需要回滚 | 在“管理版本”找到历史已发布版本，点击“切换到此版本”；确认目标版本及收费后切换。 |
| 发布成功但市场仍没有应用 | 检查应用是否暂停或被平台禁用，按应用状态处理。 |
| 操作时提示状态已变化 | 刷新应用列表，按最新状态操作；其他窗口可能已完成审核、撤回或发布。 |
| 撤回后无法删除应用 | 已经提交过审核的应用保留历史。仅从未提审、从未发布的草稿支持删除。 |

发布命令及包格式参见 [应用发布规范](APP_MARKET.md)。
